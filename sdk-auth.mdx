---
title: "SDK authentication"
description: "Authenticate SDK-related API calls"
---

The SDK uses the same credentials as the Modular API: a `client_id` and a `client_secret`. Contact support if you need credentials for your integration.

## Client ID

The `client_id` is public and identifies your integration. Use it to initialize the SDK in the browser:

```js
const sdk = Skor({
  clientId: "YOUR_CLIENT_ID",
});
```

## Client secret & server-side access token

The `client_secret` is used only for server-side calls. Keep it secure and never expose it in client-side code.

Server-side SDK calls (creating a tenant and minting an onboarding token) authenticate with a Bearer access token, generated by exchanging your credentials at `/authenticate/token` using HTTP Basic Authentication:

```bash
curl -X POST "https://api.skortorent.com/api/v1/authenticate/token" \
  -u "$SKOR_CLIENT_ID:$SKOR_CLIENT_SECRET"
```

Send the returned token as a bearer token on subsequent server-side requests:

```http
Authorization: Bearer <token>
```

The browser profile session itself is authenticated by the tenant **onboarding token** (minted server-side via `/tenants/onboarding-token/{tenantId}`), so the `client_secret` never reaches the browser.

<Warning>
  Never expose your client secret or server access token in browser code, mobile apps, logs, or public repositories.
</Warning>
